# qBpanel 26.11.15 · 一键更新失败路径

## 改了什么

只动两处功能，其余是配套清理。

### 4 · 失败时显示安装日志

升级脚本装完新包起不来会自己回滚，回滚记录写在设备的 `update/install.log` 里。
`GET /api/update/status` 每次轮询都把这文件最后 12 行放进 `st.log` 回传，
但前端只取了 `phase` 和 `detail`，日志从来没有出口——用户只能看到一行红字。

现在它渲染在状态条下方，等宽字体、7 行高度、超出滚动。

三个约束是必须的：

| 约束 | 原因 |
|---|---|
| 只在 installing 及之后出现 | `install.log` 是追加写的，下载阶段里面是**上一次**的记录，提前显示会让人以为刚发生了回滚 |
| 每次尝试开始时截空 | 后端 `start_update()` 里 `open(..., "wb")`，避免上一轮内容混进本轮 |
| 高度按整行算 | `max-height = 7 × 20px + 10px`；溢出内容会画进 padding 区，底部 padding 挡不住任何东西 |

### 4c · 失败原因翻成可读说明

下载阶段抛异常时，服务端把 `str(exc)` 直接塞进 detail。现在改走 `describe_error()`，
并给这个函数补了四个分支：

| 异常 | 结果 |
|---|---|
| `HTTPError 403` | HTTP 403（GitHub 接口限流） |
| `HTTPError 404` | HTTP 404（仓库或发布不存在） |
| `socket.timeout` | 请求超时 |
| `socket.gaierror` | 域名解析失败，请检查设备的网络与 DNS 设置 |
| `ConnectionRefusedError` | 连接被拒绝，对方没有应答 |
| `ConnectionResetError` | 连接被中断，请重试 |
| `ssl.SSLError` | TLS 握手失败，请检查设备的证书与时间 |
| 其它 | 原文（不隐藏） |

`URLError` 改成递归解包 `reason`，因为 urllib 会把真实原因包一层。

## 顺带修掉的两个问题

### 下载阶段丢文件名

`applyUpdateState()` 在 `phase === "downloading"` 分支里无条件把 detail 覆盖成固定文案，
26.11.3 记的「同步显示实际文件名」效果被 26.11.9 重写时吃掉了。

现在服务端只下发语言中立的文件名（`st.file`），文案由前端按当前语言拼：
`正在下载 {file}` / `Downloading {file}`。这样英文界面不会冒出中文句子——
原来的 detail 是中文字符串，直接回显在英文界面里就是错的。

### 回滚后弹窗永不消失

脚本回滚后新起的仍是旧版本，接口回到 `idle` 且 `current` 与升级前相同。
原先的轮询只认「版本变了」和「连续失败 180 次」两个终止条件，这种情况会一直轮询下去。

现在加第三个条件：**见过 downloading/installing 之后又回到 idle，且版本没变** → 按失败收尾。
用 `_updateSawActive` 记录「这次真的看到过安装过程」，避免开机第一次读到的 idle 误判。

提示语按日志内容区分：有 `rolling back` 就说「已回滚到当前版本」，没有就说「等待超时，请到应用中心确认」。

## 装到设备的方式

本地打包脚本 `tools/build_fpk.py` 依赖已失效的 WorkBuddy 环境
（`VENV_PY` 指向不存在的路径），本轮改为手动打包：本地打 tar → scp 到 `fnos-test` →
远端 `fnpack build` → 取回 → `verify_fpk.py` 校验。CI 走的是另一套，不受影响。
